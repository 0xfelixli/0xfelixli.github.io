把自己 8 个月、11373 条 prompt 翻出来看了一遍：我和 Agent 协作的坏习惯、盲区和知识缺口

12 Sep, 2026
|

把自己 8 个月、11373 条 prompt 翻出来看了一遍

我让 Agent 读完了我过去 8 个月和 Claude Code、Codex 的全部对话记录。

不是让它总结”学到了什么”，而是让它只看我自己打的那些字，回答三个问题：我在和 Agent 交流的时候有哪些不好的习惯？哪些地方一直在重复浪费？我反复问”这是什么”的东西，暴露了哪些知识缺口？

结论不太好看，但很具体。这篇是复盘。

太长也要读

  • 8 个月，3418 个会话，我亲手打了 11373 条 prompt。8 月一个月 5821 条，是 7 月的 7 倍。
  • 数量涨的同时，每条 prompt 的信息量在掉：中位长度从 4 月的 91 字掉到 9 月的 20 字，10 字以内的占比从 16% 涨到 29%。
  • 最常打的三句话是”实施”（141 次）、“继续”（109 次）、“做的咋样了”（96 次）。
  • 354 条 prompt 以”吧 / 对吧 / 对不对 / 是不是更好”结尾。我一直在引导 Agent 同意我。
  • 393 次”这是什么 / 帮我理解”。同一个核心概念（门限签名）被讲了三遍，5 个月后我还是说”我还是不理解”。
  • 两天前做过一次类似的分析，Agent 给了四条改进规则。两天后全局配置文件一个字没动。

最后一条最值得记：分析做完不落地，等于没做。

一、数据从哪来

本机有两份原始记录：Claude Code 的 ~/.claude/projects/，Codex 的 ~/.codex/sessions/，都是 JSONL，加起来 3.3 GB。我用 funes 把它们索引成可检索的记忆，再写了一个几十行的脚本，只抽出 role=user 且来源是真人输入的消息，过滤掉系统注入、工具回传、子 agent 的任务书。

剩下的就是我自己一个字一个字打出来的东西。

指标数值
时间范围2026-01-05 到 2026-09-12，140 个活跃日
会话数978 个有真人输入的会话（总 3418，其余是自动化流水线）
prompt 数11373（Claude Code 4936，Codex 6437）
涉及目录177 个
模型输出约 1.25 亿 token（Claude 6980 万，Codex 5500 万）
手动中断158 次，其中 8 月 99 次

8 月是分水岭。那个月我开始同时开多个终端面板跑多个 Agent，量上去了，每条 prompt 却越来越短。这不是巧合，后面几条坏习惯基本都是从这里长出来的。

二、六个坏习惯

1. 一字令和代词式追问

10 字以内的 prompt 有 2862 条，占四分之一。排在最前面的是：

实施          141
继续          109
做的咋样了     96
好的          34
要的          29
改动大吗       26
现在呢        13
如何改呢       11

“实施”本身没问题，它是在 Agent 给完方案之后的批准。问题在于批准的时候我几乎从不补一句验收标准。“实施""继续”这类一字批准一共 285 次，紧跟着的下一条 prompt 有 37 次是”为什么……""不对……""还是……”这类返工。方案被批准了，但”做完的样子”从来没被说清楚。

“现在呢""这些呢""改法呢”更糟。它指哪件事、要什么粒度、要不要跑命令验证，全靠 Agent 猜。猜错就是整整一轮白跑。

改法：每条 prompt 至少带三样东西：对象、动作、验收方式。“现在呢”改成”刚才那 4 个 TODO 现在各是什么状态，跑一次测试后回答”。多打十几个字，省一轮。

2. 催进度，而不是要汇报

“做的咋样了""做完了吗""跑的咋样了”一共出现 96 次。

这暴露的不是我着急，而是我把任务派出去的时候没有定义完成信号。Agent 在后台跑，我不知道它到哪了，只能隔一会儿戳一下。每戳一下都是一轮上下文消耗，而且 Agent 为了回答”做得咋样”还得先自己盘一遍状态。

改法：派任务的时候一句话说清”做完的标志”：写到哪个文件、最后一行输出什么、哪个测试变绿。长任务要求它每完成一个阶段主动汇报三行，我不再主动问。

3. 引导式提问

354 条 prompt 以”吧 / 对吧 / 对不对 / 是不是更好”结尾。典型的一条：

肯定是 1 啊 对不对 做代码审计是有调用关系的 别的又能会调用 肯定要读到啊 同一个仓库中其他目录能读到是合理的啊对吧

这不是提问，这是要求附和。模型面对这种句式的默认行为就是顺着说。我得到的不是判断，是回声。

讽刺的是，我另一边又有 129 次在要求”对抗式审查""证伪""给我反驳理由”，还写过”你不要臆想，做事要有证据”。说明我知道该怎么问，只是在有倾向的时候忘了。

改法：凡是自己已经有答案的问题，反着问。“是不是 1 更合理”改成”给我两条 1 不成立的理由，再给结论”。

4. 一个会话装下四天

超过 50 条 prompt 的会话有 45 个。最长的一个 428 条，从 7 月 31 日开到 8 月 4 日，开头是”对这个文件你有什么看法”，中间经历了性能优化、删模块、协议设计、召回率讨论，结尾是”作为一个工作 10 年的工程师系统性地 review 下整个流程”。四天的工作塞进一个上下文里，后半程的判断全是被前半程的残留拖着走的。

还有一个更典型的：9 月 5 日晚上我说”这里面的中文输入有问题，帮我分析下”。这个会话跑了 1400 多轮、13 个小时，中途换了两次 UI 组件库，做了一次整体重设计，最后一条是我自己说的”还是按照终端的方式，不要分别处理了”。绕了一圈，回到起点附近。

问题不在 Agent 跑偏，在于我没给边界。“帮我分析下”没有说”只修输入法，别碰别的”。一个开放式的开头加上一个不换会话的习惯，就会长成这样。

改法：一个问题一个会话。会话过 100 轮或者话题明显换了，让它先写一份 HANDOFF.md（做到哪、下一步、坑），新会话读文件接手。我口头转述必然丢信息。

5. 情绪化连问

9 月 8 日一个会话里，我连着问了四遍”为什么没有发现""为什么没发现呢""所以为什么没有发现呢”，最后一条是”所以到底发没发现？你给我说出最核心的一句话就行了，不要搞什么很大的段落，我也没有耐心看”。

最后那句其实是对的。它说清了我要什么：一句话结论。但它应该是第一句，而不是第四句。前三句只是同一个问题换了语气重发，Agent 每次都认真地又铺一大段，我每次都更烦。

“还是不行”出现了 16 次，集中在几个前端和输入法的问题上。连说三次”还是不行”，说明我提供的信息（截图、复现步骤、环境）和上一次一模一样。Agent 拿到的输入没变，输出当然也不会变。

另外一个数字：23 点到凌晨 4 点之间的 prompt，8 月有 488 条，占当月 8%。上面几条坏习惯在深夜时段明显更密。

改法：同一个问题问到第二遍，就停下来换方式：要么补新证据（截图、日志、复现命令），要么明确要求输出格式（“一句话""一张表”）。重复问第三遍等于承认自己没在思考。

6. 分析做了，规则没落地

9 月 10 日我做过一次类似的复盘，让 Agent 看我最近两天的对话。它给出了四条建议，写好了可以直接粘进 ~/.claude/CLAUDE.md 的文本，并问我”要不要我直接写进去”。

我没有回答。今天检查，那个文件的修改时间还停在 9 月 6 日。Codex 的全局 AGENTS.md 是 0 字节。

同类的还有：45 个会话以”hi”开场，47 次要求”用中文回复”。这些都是应该写进配置一次、以后再也不用打的东西。习惯要改一辈子，规则改一次就够，而我选了更贵的那条路。

改法：任何”以后要注意”的结论，当天写进 CLAUDE.md 或 AGENTS.md，不写就不算复盘完成。

三、393 次”这是什么”暴露的知识缺口

我把所有含”是什么 / 什么意思 / 帮我理解 / 大白话说下”的 prompt 拉出来，按主题归了一下。有几类值得单独说。

每天在用的工具，基础词汇不认识。 用了几个月的代码评审平台，8 月底才问”PHID 是什么意思”，9 月初问”LGTM 是什么意思”。还有”e2e 是什么""orchestrator 是什么意思”。这些词一天在屏幕上出现几十次，我一直靠上下文猜着用。

业务核心的密码学，讲了三遍还没懂。 门限签名（MPC/TSS）是我所在行业的地基。4 月 Agent 给我解释过一遍私钥分片，9 月 7 日我又问”MPC 是什么，帮我理解”，9 月 9 日我说：

我对于这个 mpc 的技术实现我还是不理解 为什么可以分成多个私钥以及在签名的时候为什么不会合成一个私钥

三次解释，每次都听懂了，每次都没留下。因为我每次的动作都是”看一遍解释，觉得懂了，关掉”。没有笔记，没有复述，没有在一周后自己再讲一遍。让 Agent 解释一个概念，和学会这个概念，是两件事。

基础设施和网络。 “source IP 是什么，如何看""为什么局域网的两台机器不能直连""这个环境变量是什么意思""限制对源服务器的直接访问是什么意思”。这类问题都是运维基础，出现频率不高但每次都卡住整个任务。

前端安全的细节。 “Next.js 缓存为什么会影响到别人""nonce 为什么之前是用户可以提交的""这里应该要有个 XSS 为什么没有执行”。做安全审计的人对前端框架的运行机制不熟，判断漏洞是否成立就只能靠 Agent 的说法。

本地模型的名词。 GGUF、Q4_K、MLX、abliterated，8 月中一连串地问。这一类反而问题不大，用两次就记住了。

自己设计的系统，自己看不懂。 “大白话说下”出现了 23 次，其中大部分是在读 Agent 对我自己项目的输出。“unauditable 这个命名是什么意思，别人一眼能看懂吗""这些是什么意思，我没有理解”。这不是知识缺口，是设计问题：抽象层太多，命名太晦涩，连作者都要翻译。

改法：建一个”问过的概念”清单。每个概念用自己的话写 3 行，一周后让 Agent 当面试官考我。9 月 9 日我其实这么干过一次：“你是面试官，关于这些内容问我一个问题，要能分辨出我到底懂不懂”。那一次效果很好，应该变成每周例行的事。

四、做对的事，别丢

复盘不能只挑毛病，有几件事我做对了，而且数据上看是这几个月才养成的：

  • “先不要动手，先和我聊清楚” 出现 234 次。5 月之前几乎没有，9 月占到全部 prompt 的 3.1%。它把讨论和执行分开，是我最有效的一句话。
  • “复述我的需求” 41 次。让 Agent 先说它理解的任务，错了立刻纠正，比做完再改便宜十倍。
  • “改动大吗” 26 次，加上各种问成本、问工作量的一共 149 次。这是在动手之前给自己一个决策点。
  • 对抗式审查 129 次。把方案发给多个独立会话，分别从第一性原理、对抗、消融、奥卡姆剃刀、批判性思维几个视角评审，同一天群发同一段 prompt 到三个以上会话有 76 次。
  • 派一个零上下文的 Agent 只读文档做推演，用来检验文档写得够不够清楚。它找出的缺口比我自己 review 狠。

这些不是技巧，是把”怀疑”变成了默认动作。要继续。

五、接下来 30 天的规则

写进配置，不靠记忆：

  1. 每条 prompt 带对象、动作、验收方式。不允许单独发”实施""继续""现在呢”。
  2. 派长任务时定义完成信号和汇报节奏。不再问”做的咋样了”。
  3. 自己已有答案的问题，改成”给我两条反对理由”。
  4. 一个问题一个会话。超过 100 轮或话题切换，先写 HANDOFF.md 再开新会话。
  5. 同一问题第二遍，必须附带新证据或明确输出格式。
  6. 任何”以后注意”的结论当天进 CLAUDE.md / AGENTS.md。
  7. 概念清单：每周把新问过的”这是什么”写 3 行，周末让 Agent 出题。
  8. 每周跑一次这套脚本，只看三个数：10 字以内 prompt 的占比、“做的咋样了”的次数、“我的意思是”的次数。这三个数不降，说明上面七条没执行。

六、怎么复现这个分析

方法比结论有用。整个过程不到一小时。

  1. 安装 funes，让它索引 ~/.claude/projects 和 ~/.codex/sessions。它提供 sessions、recall、scan、get 几个接口，可以按语义找、按字面搜、按会话读。
  2. 写一个脚本遍历原始 JSONL，只保留真人输入。Claude Code 的记录看 type == "user" 且 origin.kind == "human"；Codex 看 response_item 里 role == "user" 的 input_text，再按 originator 过滤掉自动化任务。
  3. 统计几组数：长度分布、每月趋势、高频短句、以特定词结尾的比例、同一会话里连续出现的纠正句。
  4. 把”是什么”类的 prompt 单独拉出来，按主题归类。这一步用 Agent 归比自己归快。
  5. 挑几个最长的会话，用 sketch 看它开头和结尾在聊什么。漂移一眼就能看出来。

最后一句给自己：这些记录本来就在硬盘上，占了 3.3 GB，我从来没打开过。最便宜的自我改进数据，一直躺在那里。
